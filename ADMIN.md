# Админка Amura — /control

https://badoo.whales.team/control — веб-админка (мобильному приложению не нужна). Сделана по общему шаблону
админок на Go1 — см. `../Go1/SUPERADMIN.md` (структура, как развернуть в новом проекте, как наращивать).

## Первый запуск / после обновления

```sh
badoo1deploy --skip-tests                       # выложить (миграции применяются при старте)
make control-super WHO=denis24art@gmail.com     # назначить суперадмина (из папки BadooGo1)
```

- Порядок важен: команда `control/super` есть только в новой сборке. «Неизвестная команда "control/super"» —
  значит, на сервере ещё старая версия, сначала `badoo1deploy`.
- «Пользователь не найден» — этот email ещё ни разу не входил: зайти на https://badoo.whales.team через Neuronet,
  потом повторить `make control-super`.
- Суперадмину открываются все разделы, его права из админки не меняются, новые разделы появляются у него сами.
- Остальных админов назначают в «Система → Права»: найти пользователя → включить нужные разделы.
- Локально: `go run . control/super <email или id>`.
- Строку «unnecessarily importing … go-sqlite3/embed» в выводе можно не замечать — безвредное предупреждение библиотеки.

## Разделы

| раздел | адрес | что |
| --- | --- | --- |
| Дашборд | `/control` | люди (всего, новые, онлайн, DAU/WAU/MAU, Premium), пары, сообщения, голоса, встречи, очереди модерации, графики за 30 дней, города, новые анкеты и жалобы |
| Пользователи | `/control/users` | ~20 фильтров (в адресе страницы — ссылкой можно поделиться); карточка `/control/users/view?uid=` с вкладками: анкета и фото, активность, пары и переписка, симпатии, гости, жалобы и блокировки, устройства, встречи, журнал |
| Переписка | `/control/chats` | все диалоги, поиск по участнику и тексту, поиск сообщений по всем диалогам, просмотр диалога, удаление сообщения |
| Встречи | `/control/meetups` | предстоящие / прошедшие / тестовые, кто идёт и отметился, удаление |
| Модерация → Жалобы | `/control/reports` | новые / приняты меры / отклонены; заблокировать или отклонить сразу все новые жалобы на человека |
| Модерация → Верификация | `/control/verification` | селфи рядом с фото анкеты: подтвердить / отклонить |
| Модерация → Фото | `/control/photos` | лента всех фото, удаление |
| Система → Журнал действий | `/control/log` | кто из админов что сделал (`control_log`) |
| Система → Права | `/control/permissions` | админы и их разделы, разделы меню и группы |
| Система → Входы и сессии | `/control/sessions` | сессии приложения (платформа, вход, срок), «завершить» одну сессию; незавершённые попытки входа (на каком шаге застряли, сколько попыток на почту) |
| Система → Состояние системы | `/control/system` | коммит и время сборки, ядро Go1, память, отклик и версия БД, строки в таблицах, миграции (и неприменённые), очередь задач и её ошибки, какие интеграции включены (только да/нет), хвост логов web/worker/cron (только суперадмину) |
| Аналитика → Воронка и удержание | `/control/analytics` | воронка когорты по дате регистрации (анкета → фото → лайк → пара → сообщение → переписка), активность за период, голоса/сообщения/пары по часам, удержание по неделям (1/7/14/30 дней) |
| Аналитика → Симпатии и антиспам | `/control/votes` | кто голосует подозрительно (лайкает почти всех, ни одной взаимности, новый аккаунт, есть жалобы), лента голосов с ответным голосом |
| Аналитика → Гости | `/control/visits` | кто смотрит больше всех анкет (сотни в час — бот/парсер), чьи анкеты смотрят, лента просмотров |

Разделы «Аналитика», «Входы и сессии» и «Состояние системы» только читают данные приложения (единственное действие —
«завершить сессию», то же, что «выйти везде», но для одного устройства). Контракт API с мобильным приложением они не меняют.

**Выгрузка CSV** — кнопка «CSV» в «Пользователях», «Жалобах» и «Журнале действий»: по текущим фильтрам, до 50 000 строк,
открывается в Excel. Каждая выгрузка пишется в журнал действий (в файлах — почты людей).

В меню — счётчики новых жалоб и селфи на проверке.

## Действия с пользователем

Заблокировать / разблокировать (с причиной), верификация, Premium (+N дней / снять), правка анкеты (имя, о себе,
город, выключить невидимку), удалить фото / сделать главным, «выйти везде», удалить аккаунт (только суперадмин).
Всё пишется в журнал действий.

**Блокировка** (`users.banned`, `components/users/moderation.go`):
- выход на всех устройствах: Bearer-токены приложения удалены, `auth_key` сменён (cookie сайта не работает);
- войти заново нельзя: `neuronet.syncUser` отвечает «Аккаунт заблокирован. Причина: …»;
- `auth.Finder` не находит заблокированного — сайт считает гостем, API отвечает 401;
- анкета пропадает у всех: колода, «Рядом», симпатии, пары, гости, чаты (`users.NotBlocked`), встречи (`goingNotBlocked`);
- push-токены удалены, непрочитанные от него у собеседников обнулены, новые жалобы на него закрыты.

Защита: нельзя заблокировать себя и суперадмина; админа блокирует только суперадмин.

## Вёрстка страниц — общие правила

Стили админки — `web/theme/adm/css/amura.css` (поверх темы StockGo1 и CoreUI). Чтобы страницы не «ехали»:

1. **Никаких инлайн-стилей для раскладки** (`float`, `height`, `margin` у полей и кнопок). Нужен приём, которого нет —
   добавить класс в `amura.css` с комментарием, а не `style="…"` во вьюхе. Инлайн допустим только для разового
   цвета или ширины колонки.
2. **Фильтры — `.am-filters`**: каждое поле — `.form-group` с `<label>` и одним `.form-control`. Высота у всех
   полей одна (`--am-h`, 34px) — тема задаёт `select` свою высоту, в `amura.css` она перекрыта.
3. **Блок без своего поля** (счётчик, флажки, кнопка) — `.form-group.am-auto` с `<label>&nbsp;</label>` и
   `.am-inline` внутри: так он стоит на одной линии с полями. Прижать вправо — `.am-push`.
4. **Флажок** — `<label class="am-check"><input type="checkbox"> текст</label>`.
5. **Шапка списка** с действиями (CSV, «Добавить») — `.am-list-head`: заголовок `h4` слева, `.am-actions` справа.
   Не `float:right` внутри `h4` — кнопка наезжает на таблицу.
6. **Выбор в строке текста** («За период [7 дней]») — `select.form-control.am-inline-select`.
7. **Карточки сводки** — `.dash-cards` / `.dash-card`, сетки — `.dash-grid`, статусы — `pill(текст, цвет)` из
   `amura.js`, пустой список — `empty_row()`.
8. **Таблицы** оборачиваются в `.am-table-wrap` сами (`amura.js`, и те, что дорисованы позже): на узком экране
   таблица прокручивается внутри карточки. Свою обёртку не делать. Если таблица в узкой карточке не помещается даже
   на компьютере — убрать колонку (перенести в подпись под именем), а не полагаться на прокрутку.
9. **Вкладки** `.nav-tabs-si` на узком экране листаются вбок — длинные подписи вкладок это переживут.
10. **Длинная плашка-пояснение** — `pill(…)` + класс `am-pill-wrap`, иначе она не переносится и растягивает страницу.
11. **Новая страница** — проверить на ширине 1400px и на телефоне (375px): подписи в ряду на одной линии, ничего не
    наезжает, у страницы нет горизонтального скролла.
